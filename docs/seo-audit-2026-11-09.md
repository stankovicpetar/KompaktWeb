# KompaktWeb SEO audit — November 9, 2026

## Confirmed findings and scope

Read-only production checks on November 9, 2026 found a mismatch between Workers Static Assets routing and the site's SEO URLs. Every project/service clean URL returns `200`, but its HTML canonical points to the corresponding `.html` URL. That `.html` URL returns `307` back to the clean URL. Hreflang, Open Graph URLs, JSON-LD page/service/breadcrumb URLs, sitemap entries and internal links also used those redirecting `.html` URLs.

The local fix aligns these signals with the existing final URLs. Physical HTML filenames stay the same. This does not introduce new routes or change Cloudflare's HTML handling. The homepages already had correct directory canonicals, so those canonicals remain unchanged.

No cross-language canonicalization was found: Serbian, English and Russian pages each pointed to their own language's `.html` variant. The translated project pages contain localized main content. Existing reciprocal `sr`, `en`, `ru` and `x-default` annotations were present; their project/service targets needed URL normalization. Serbian remains `x-default`. This matches [Google's localized page guidance](https://developers.google.com/search/docs/specialty/international/localized-versions).

The supplied Search Console report identifies real conflicting URL signals, but its age and Google's currently selected canonical cannot be established from HTTP responses. Only the owner's indexed URL Inspection results can establish that. No Search Console account was accessed, and no indexing success is claimed.

### Dashboard instructions only if WWW fails again

1. Open Cloudflare → the `kompaktweb.rs` zone → **DNS → Records**. Filter for the exact hostname `www.kompaktweb.rs`. Inspect existing records and any Workers Custom Domain ownership before editing. Reuse the existing working proxied WWW record; do not add duplicates, remove the apex record or change the working `kompaktweb.rs` custom domain. If an existing WWW record is DNS-only, enable proxying on that record if it is intended for this redirect.
2. Only if **no WWW record or managed WWW custom-domain record exists**, add a redirect-only DNS record: **Type A**, **Name `www`**, **IPv4 `192.0.2.1`**, **Proxy status Proxied**, **TTL Auto**. This placeholder is Cloudflare's documented redirect-only setup; it is not an origin server. Do not create a second WWW record alongside an existing A, AAAA or CNAME record.
3. Open **Rules → Redirect Rules** (or **Rules → Overview → Create rule → Redirect Rule**). Inspect existing Single/Bulk Redirects and Page Rules first. Correct an existing equivalent WWW rule rather than creating a duplicate. For a new Single Redirect use:

   - Name: `WWW to canonical hostname`.
   - Match: **Custom filter expression**, `(http.host eq "www.kompaktweb.rs")`.
   - URL redirect type: **Dynamic**.
   - Target expression: `concat("https://kompaktweb.rs", http.request.uri.path)`.
   - Status: **301**.
   - **Preserve query string: Enabled**.

4. Save/enable the rule. Put it before other matching Single Redirect rules that would send WWW elsewhere. The exact-host condition keeps the apex out of this rule and avoids a self-redirect. Test HTTP and HTTPS, root, language paths and a multi-parameter query using the commands below.
5. Retain the existing apex Worker domain and API routing. Workers Custom Domains match exact hostnames, so editing `src/index.js` alone cannot repair WWW traffic that never reaches that Worker. A zone redirect executes separately from the site's contact implementation. Send form submissions directly to the canonical host; do not rely on a hostname `301` to preserve a POST request body.

References: [Cloudflare redirect-only DNS and dynamic rule example](https://developers.cloudflare.com/fundamentals/manage-domains/redirect-domain/), [hostname redirects](https://developers.cloudflare.com/rules/url-forwarding/examples/redirect-all-different-hostname/), [Workers Custom Domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/).
